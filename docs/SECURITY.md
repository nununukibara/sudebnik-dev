# SECURITY AND PUBLIC-SAFE RULES

公開・非公開を問わず守る安全規則です。

## Gitへ入れないもの

- `.env`と環境固有設定
- APIキー、OAuthクライアントの秘密、リフレッシュトークン、アクセストークン
- パスワード、秘密鍵、証明書の秘密部分、支払い情報
- 実在利用者の個人情報、会話、位置情報、連絡先
- 本番データベースやバックアップ
- 権利・ライセンスが確認できない画像、音声、動画、フォント
- 大容量の生成物、書き出し動画、一時ファイル
- 個人のPCだけで通用する絶対パスやホスト情報

サンプル設定は`.env.example`へ**架空値だけ**を置きます。

## 秘密情報の置き場所

秘密値は、OSの資格情報管理、ホスティング先のSecret機能、GitHub Actions Secrets、権限を絞った環境ファイルなどへ置きます。採用した保存方法はARCHITECTUREへ「場所の種類」だけを書き、値は書きません。

## サンプルデータ

- 架空の名前と内容を使う
- 画像・音声・動画・フォントは自作、明示的に再配布可能、または生成権利を確認したものにする
- 元データを匿名化しただけのものは、復元可能性を確認する
- ファイルのメタデータにも個人情報がないか確認する

## 外部サービス

導入前に次を判断者へ示します。

- 送信されるデータ
- 保存地域・保存期間が分かるか
- 課金と上限
- 利用規約・ライセンス
- サービス停止時の動作
- 削除・移行方法

## 破壊的操作

削除、上書き、移行、本番反映、公開範囲変更の前に対象を読み取り確認し、判断者の許可を得ます。可能ならバックアップ、dry-run、試験用データを使います。

## 公開前チェック

**公開してよいかの条件はここが正本です。**版を確定してよいかは[VERSIONING.md](./VERSIONING.md)、検証が足りているかは[TESTING.md](./TESTING.md)にあります。

- [ ] `git status`と公開予定差分を確認した
- [ ] 秘密値らしい文字列を検索した
- [ ] 個人名、メール、電話番号、住所、ローカル絶対パスを確認した
- [ ] 実データ、ログ、画像メタデータを確認した
- [ ] 素材と依存関係のライセンスを確認した
- [ ] READMEに公開してよい説明だけがある
- [ ] Issue、PR、Actionsログにも秘密がない
- [ ] 公開ライセンスを人が選んだ

## 漏えいに気づいたとき

1. チャットやIssueへ秘密値を再掲しない
2. まず該当キー・token・パスワードを失効または変更する
3. 影響範囲を確認する
4. Git履歴の書き換えが必要なら、共同作業者への影響を説明し、人の承認後に行う
5. 原因と再発防止を、秘密値を含めずWORKLOGへ記録する
